# marginstv (C++) — test plan

Status: for approval. The data generators and log tools below exist and
have been run against the Python program. The C++ test code in layers 1–2
is written in step 3, alongside the code it tests, against the golden data
listed here.

The standard for passing is the same everywhere: the C++ program produces
exactly what the Python program produces. Only wall-clock times may differ.

## Layer 1 — unit tests (C++, Catch2, seconds)

Read golden data written by `golden/dump_golden.py` from the Python code.

| Test | Golden file | Checks |
|---|---|---|
| `test_pyformat` | `units.json.gz` → `float_str` | 3,000+ floats: C++ text equals Python `str()` and `{:.2f}`, including `inf`, `1e+16`, `5e-324`, `-0.0`. |
| `test_pyset_order` | `units.json.gz` → `set_order` | 2,000 sets built as `derive_winners` then `generate_children` build them: C++ iteration order equals CPython's. |
| `test_prefix` | `units.json.gz` → `prefix` | 1,500 random prefixes: `compute_last_round`, `get_order_q` (values and order), `merge_outcome`, canonical bytes, BLAKE2b signature in both quota modes. |
| `test_equivalence_classes` | `units.json.gz` → `equivalence_classes` | Class count and order of class rankings. |
| `test_readers` | `inputs.json.gz` | For 9 data files (`.txt`, `.json`, `.blt`, including VIC 2019): candidate ids, ballot count, a hash of every ballot's votes and ranking, first-preference tallies, the three metadata tables. |
| `test_simulate` | `inputs.json.gz` | Quota, total votes, outcome order, round tallies, WEUB, simple UB, and the simulation's log text character for character. |

## Layer 2 — replay tests (C++, about a minute)

`dump_golden.py` runs the Python search in-process and records every call to
`eval_child_initial`, `generate_children`, `eval_child` and
`solve_stvdistance`, with inputs and outputs stored exactly. The C++ test
feeds each recorded input to the matching C++ function and requires an exact
match on every output field: every bound, transfer value and per-round mask
in the elimination/quota context, every entry of the displacement tables,
every child generated, and the round tallies shared between children.

Cases (up to 400 children each):

- **Bounds:** 3 instances (Langside, Minneapolis 2009, `paper_example.blt`)
  × every bound configuration: {none (BST19), `-eqlb`, `-eqlbc`} ×
  {none, `-dlb`, `-dlbc`} × {ranges, `-useqprefix`} × {`-prec_et` off, on}.
  That's 36 configurations per instance, with MINLPs off.
- **MINLP models:** the same 3 instances, both quota modes, with and without
  `-m`, under `-allminlps`. Each recorded solve keeps the model file SCIP
  received (`.cip`), its changed parameters (`.set`) and its objective
  limit. The C++ test builds the same model, writes it through SCIP, and
  requires identical files, then solves it and requires the same status and
  bounds.

A failure here names the exact function, child and field, which a log
difference cannot do.

## Layer 3 — end-to-end log tests (`e2e/run_e2e.py`)

Runs the C++ binary with the reference flags and compares its log line by
line (`e2e/compare_log.py`). Lines reporting wall-clock time are ignored.

**Reference set A: `15PC_logs` (222 runs).** `e2e/make_manifest.py` lists
each run's data file, seats, flags and upper bound in
`e2e/reference_runs.csv`. I confirmed the flags by rerunning the Python and
matching the logs. FedAus runs predate the current version mapping, and their
version 10 was identified by trial. Ending states:

- 185 converged: must match exactly.
- 35 stopped on the time limit, 2 killed mid-run: the C++ log must contain
  the whole Python log at its start, and may carry on past it. The runner
  stops the C++ program once it has gone past the end of the reference.

**Reference set B: extra Python references (about 120 runs).** Generated by
`e2e/make_extra_refs.py` into `e2e/extra_refs/`, covering what set A never
uses:

- every bound configuration (36 per instance, Langside and Minneapolis 2009)
- current versions 11–15, which have no 15PC log
- `-allminlps` in both quota modes, `-evalpara`, `-pc 1`, no `-m`, no `-ub`,
  `-agap 1`, no `-lse`, BST19 bounds only
- `.blt` input, and `-just_sim` for every input format
- JSON input under search (ACT 2022, NT 2019), cut off after 60 s and
  compared as a prefix

Set B also keeps stdout and the MINLP sidecar (`.solves.csv`). For runs that
finish, the C++ summary line must match with its two time columns ignored.
The sidecar must match as a set of lines with its two time columns ignored,
because parallel solves finish in any order.

**Tiers**, by how long Python took on the reference machine:

| Tier | Selection | Runs | Use |
|---|---|---|---|
| quick | Python ≤ 60 s | 59 of set A, all of set B | every build |
| medium | Python ≤ 30 min | 80 of set A | before each commit to main |
| full | everything | 222 + set B | before a release; overnight |

## Layer 4 — thread-count independence

Every end-to-end run in the quick and medium tiers runs at `-threads 1,2,4,15`.
Each log must match the reference, and therefore each other. This is the test
that the search order depends only on `-pc`, never on scheduling.

Built with ThreadSanitizer (`-fsanitize=thread`), the replay tests and the
quick tier must run with no reports. The address and undefined-behaviour
sanitizers are run the same way.

## Layer 5 — SCIP running in threads

Before anything depends on it: the recorded models (layer 2) are solved 8 at
a time in separate threads, repeatedly, and every result must equal the
single-threaded result. This includes models large enough to use Ipopt. If
this fails, MINLP solves move to helper processes (see ARCHITECTURE.md).

## Layer 6 — speed and memory (reported, not pass/fail)

On VIC, NSW, QLD 2019 and ACT, NT 2022, run C++ and Python for the same wall
time with `-pc 15` and the same flags. Report nodes expanded, lower bound
reached, and peak memory (`/usr/bin/time -l`). Also report C++ at 1, 4 and 15
threads, to show how the speed scales with cores. The aim stated for the
project is more progress per unit time at lower memory; these numbers show
whether that was achieved.

**Platform differences.** Eleven converged runs (Dublin North 3/5/8/9,
Dublin West 3/4/5/6/8/9, Maryhill 5) differ on this Mac from their
references, for the Python and the C++ program alike. A few MINLP leaf
solves find a solution just under the cutoff here but not on the server
that produced `15PC_logs`. Its Linux pyscipopt wheel is a different SCIP
build. `e2e/make_local_refs.py` regenerates such references with the Python
on this machine into `e2e/local_refs/`, and `run_e2e.py` uses those in place
of the originals. Run on the server, the C++ program should be compared
against the originals.

## What these tests cannot cover

- A MINLP solve that stops on its time limit (`-t`, `-thard`) depends on
  machine speed, so such a run cannot be expected to match. None of the
  quick-tier runs hit those limits. A mismatch in a longer run is checked
  against the `.solves.csv` sidecar to confirm a time limit caused it.
- `cap_worker_count` is not ported (threads share memory), so Python's
  warning line about reducing `-pc` never appears. No reference contains it.
